2. About our project

Project nameAgent Firewall
One-line pitchAI agents have no seatbelt. We built one: a firewall that stops hijacked AI agents before they act, and lets a human make the final call.
The problem, and who it is forAI agents now read email and web pages and then act: they send emails, move files and delete records. They cannot tell their owner's instructions from text an attacker planted, so one hidden sentence in an email can make them leak data or destroy records (prompt injection, OWASP LLM01). Agent Firewall is for any team that gives an AI agent real tools: finance, support, operations and the platforms that host agents.
Where the human comes in, and why
Theme: Human + AI: Better Together		Any tool call with a high risk score, for example sending data to an unknown address or deleting records, is paused. A reviewer sees the user's original task, the content the agent read with the hidden instruction highlighted, and the action the agent now wants to take, then allows or blocks it. Why: an AI cannot be fully trusted to decide whether another AI has been manipulated, because the same trick could fool the checker, and actions like sharing company data or deleting records need a person who is accountable. The AI handles the volume; the human handles the judgement.
What we built with Custom code: Python 3.12, FastAPI, the official MCP Python SDK (an MCP tool server and an MCP proxy that intercepts every tool call), SQLite, Jinja2 pages with Tailwind CSS and Server-Sent Events.
AI models (Groq): llama-3.3-70b-versatile runs the agent with tool calling; llama-3.1-8b-instant runs the intent check.
Firewall checks: YAML permission policy, taint tracking of untrusted text, intent check, injection-phrase signal, combined into a 0–100 risk score.

Deployment: Docker container on Alternate Clouds.
